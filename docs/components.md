# 组件化：`<use src="x.bum.xml">`

> 一句话：**组件是编译期拼进宿主元素树的 UI 片段**。运行时拿到的仍然是一棵普通节点树——
> 没有额外开销、没有新的二进制格式、命中测试/动画/热重载都与普通界面一致。

## 形态

| 文件 | 角色 | 状态 |
|---|---|---|
| `标题栏.bum.xml` | 组件源码（可读、可编辑、可热重载） | ✅ 已实现（本文） |
| `标题栏.bum` | 组件编译产物（不可读、分发用、参数表随文件走） | 🚧 规划中（见文末） |
| `<use src="…">` | 在宿主 UI 里引用组件 | ✅ 已实现 |
| `renderer.mountLayout(…)` | 运行时挂载组件（动态列表/插件） | 🚧 规划中 |

已落地示例见 [`examples/components/`](../examples/components/)：
标题栏 `titlebar.bum.xml`、按钮 `button.bum.xml`、组合卡片 `card.bum.xml`（内部再引用按钮）。

## 基本用法

```html
<!-- 宿主 -->
<use src="titlebar.bum.xml" x="0" y="0" w="720" title="文件管理器" hint="共 12 项"/>
<use src="button.bum.xml"   x="16" y="44" w="132" label="确定"/>
```

```html
<!-- titlebar.bum.xml -->
<div style="height:44; background:#16161D">
    <span style="...">{{title}}</span>
    <span style="...">{{hint}}</span>
    <button id="close" style="...">✕</button>
</div>
```

编译后得到：`<use>` 变成一个普通容器（尺寸/底色取组件根，被 `<use>` 属性覆盖），
组件根的子元素成为它的子节点。

## 参数

- `{{name}}`：用 `<use>` 上的同名属性替换；未提供 → 替换为空串 + **编译警告**。
- `{{name=默认值}}`：可缺省参数，未提供时用默认值，不报警告。
- **参数值按纯文本注入**（`& < >` 会被转义）：传进来的值里即使有 `<use>` 之类标签，
  也只是文字，不会变成真元素。想传结构请另建组件，或用 class 覆盖样式。
- 参数名大小写不敏感（属性名本来就小写化）。

```html
<button style="…; background:{{bg=#23232E}}">{{label}}</button>
```

## 合并规则

| 位置 | 行为 |
|---|---|
| 组件根元素属性 | 合入 `<use>` 生成的容器（背景、尺寸、圆角…都作为组件默认值） |
| `<use>` 自身属性 | 覆盖组件默认值；`x/y/w/h`、`left/top` 等几何属性直接生效 |
| `style` / `class` | **叠加而非替换**（`组件值 + ";" + use值`），所以传 style 不会把组件自己的背景/圆角抹掉 |
| `<use>` 上的 `src` | 不参与参数替换 |
| 嵌套 | 组件里可以再写 `<use>`；同一文件引用多次就展开多份，每个实例独立 |
| 深度 | 超过 8 层视为循环引用：警告并停止展开 |
| 组件根缺失 | 组件文件没有顶层元素 → 警告 + 空容器 |

## 资源路径

组件里的相对资源路径（`<img src>`、`<video src>`）在展开时**改写成宿主相对路径**：

```
examples/components/titlebar.bum.xml 里写 <img src="icon.png">
  → 宿主 examples/components/main.html 里得到 src="titlebar/icon.png"
```

`ResolveUI` / `LoadImages` 仍然只认"相对 UI 文件目录"，所以不需要改应用侧代码。

## CSS 是全局的（重要）

组件自带的 `<style>` 会**并进宿主的样式表**，这意味着：

- ✅ 组件可以被宿主主题化（宿主写同名规则即可覆盖）；
- ⚠️ 组件的选择器会污染宿主，宿主的也会命中组件 —— **给组件内的类加前缀**（示例统一用 `.cmp-`）；
- ⚠️ **不要用参数化组件的 `<style>`**：样式表是全局的，多个实例共享同一条规则，
  `{{bg}}` 会被最后一个实例的值覆盖。参数化的样式写**内联 `style`**（每个实例独立）：

```html
<!-- ❌ 所有实例都会共用最后一个 bg -->
<style>.cmp-btn { background: {{bg}}; }</style>

<!-- ✅ 每个实例独立 -->
<button class="cmp-btn" style="background: {{bg=#23232E}}">…</button>
```

组件内的 `:hover` / `:active` 等运行时伪类照常工作（编译成状态样式），
`@keyframes` 也可以写在组件里。

## 为什么是编译期内联（而不是运行时挂载）

运行时挂载组件要重做四件事：节点 id 全局唯一化、缩放规格（百分比/flex）重映射、
名称表命名空间、事件与滚动状态的归属。而**静态组装**（标题栏、按钮、卡片、播放器外壳）
占实际使用场景的绝大多数，编译期内联把这些问题一次性绕开：

- 二进制格式不用动（`BINUI_VERSION` 仍是 11）；
- 命中测试、绘制顺序、动画、热重载、`--watch` 全都不需要改；
- 代价是不能在运行时"插件式"加载未知组件 —— 这是下一阶段的事。

## 规划：`.bum` 二进制组件

`.bum` = 一份普通 binUI 布局 + **组件描述段**（新增可选段，恒定写出、长度前缀，同 v9/v11 的做法）：

```
uint32 compBytes + uint32 paramCount + BinUICompParam[paramCount]
BinUICompParam = { char name[16]; uint16 nodeId; uint8 target; uint8 op }   // 参数名 → 目标节点
// target: 0=文本 1=节点颜色 2=宽度 3=高度 4=class 5=style
```

两种用法，按落地顺序：

1. **编译期内联（先做）**：编译器读 `.bum`，把节点/规格/名称表/状态段整体拼进宿主布局，
   id 全局平移、名称加前缀；宿主 `<use>` 的参数按描述段应用到目标节点。
   —— 此时 `.bum` 与 `.bum.xml` 对作者完全等价，只是前者看不到源码。
2. **运行时挂载（后做）**：`renderer.mountLayout(bytes, parentId, x, y)`，用于动态列表、
   插件面板。需要 id 重映射表 + spec 重映射 + 名称前缀，工作量明显更大。

命名/后缀约定：

| 后缀 | 含义 | 谁读 |
|---|---|---|
| `.bum.xml` | 组件源码（XML/HTML 片段） | 编译器（编译期展开） |
| `.bum` | 组件编译产物（含参数表） | 编译器（内联） / 渲染器（运行时挂载） |
| `.binui` | 完整界面布局（**应用入口**） | 外壳 `loadLayout` |

`.bum` 与 `.binui` 的头部相同（`BINUI_MAGIC`/`BINUI_HTML_MAGIC`），区别只在多出的组件描述段；
没有描述段的 `.bum` 依然是一个合法 `.binui`，所以可以先用 `.binui` 顶替，后续加段不破坏旧文件。

## 当前限制一览

| 限制 | 现状 |
|---|---|
| `.bum` 二进制组件 | 编译会产生警告「二进制组件暂不支持」，按空容器处理 |
| 运行时挂载 | 未实现（可用 `renderer.addNode` 手搓简单静态节点） |
| slot / children 投影 | 未实现（组件内不能"把宿主的孩子插到这里"） |
| 组件作用域 CSS 隔离 | 未实现（CSS 全局，靠类名前缀约定） |
| 组件内 `<script>` | 忽略（没有脚本引擎） |
